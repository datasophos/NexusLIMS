# Pull request documentation previews

PR previews use a Cloudflare Pages project connected to this repository through
Git integration. Cloudflare posts preview links on pull requests. Published
release and development documentation continue to use GitHub Pages.

Before enabling this workflow, create a Pages project named `nexuslims-docs`,
connect `datasophos/NexusLIMS`, and configure:

- Production branch: `main`, with production deployments disabled.
- Preview deployments: all branches, with pull request comments enabled.
- Build command: `bash scripts/build_cloudflare_docs.sh`.
- Build output directory: `_build`.
- Build environment variables: `PYTHON_VERSION=3.11` and
  `SKIP_DEPENDENCY_INSTALL=1`.

The build reuses terminal demonstration assets from the published `latest`
GitHub Pages build. Changes to demonstrations appear after those assets are
regenerated by the full documentation build. Cloudflare builds run independently of GitHub Actions
integration tests. Cloudflare's Git integration controls which repository
branches it can build; fork contributions may need a maintainer branch.

Create an account-scoped Cloudflare API token with Pages edit permission and
store it in the GitHub Actions secret `CLOUDFLARE_PREVIEW_TOKEN`. The
reconciliation workflow uses trusted default-branch code and removes preview
deployments for closed pull requests, excluding branches that still have an
open PR. It runs on PR events and every 15 minutes. The project name and account
ID in `scripts/cloudflare_previews.py` must match the Cloudflare project.

Set up the project and secret before merging the migration; otherwise new PRs
will not receive previews once the old GitHub Pages workflow is removed.
